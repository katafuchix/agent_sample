# agent_sample
## 1. プロジェクトにサブエージェント定義を作る
Claude Codeでは .claude/agents/ ディレクトリに、役割ごとのMarkdownファイルを置きます。

```
your-project/
├── CLAUDE.md
└── .claude/
    └── agents/
        ├── researcher.md
        ├── planner.md
        └── editor.md
```

## 2. 各エージェントファイルの中身
YAMLフロントマター + プロンプト本文、という形式です。
```markdown
---
name: researcher
description: 信頼できる情報源から豆知識ネタを調査し、出典付きでまとめる担当。ユーザーがテーマを指定してリサーチを依頼したときに使う。
tools: WebSearch, WebFetch
model: sonnet
---
```

あなたはリサーチ専門のエージェントです。
与えられたテーマについて、信頼できる情報源(公的機関、査読論文、大手メディアなど)から
豆知識になりそうなネタを最低5本調べてください。

各ネタには必ず出典URLを付けてください。
薬機法・景品表示法に抵触する可能性のある表現は避けてください。
planner.md、editor.md も同様に、役割・使えるツール・出力フォーマットを定義します。

## 3. CLAUDE.mdに全体方針を書く
これは全エージェント共通のコンテキストとして参照されます。
```markdown
# アカウント運用方針
- 匿名アカウント、猫キャラクターのペルソナ
- 調査比較型のコンテンツ
- 薬機法・景品表示法を遵守
- 出典を必ず明記する
```

## 4. オーケストレーション(呼び出し方)
メインのClaude Codeセッションで、自然言語で指示するだけで、Claudeが自動的にどのサブエージェントを使うか判断します。
> 今日のテーマ「睡眠の質」で、researcher → planner → editor の順に進めて、
> 最後に投稿文を candidates.md にまとめて保存してください。
Claudeは各エージェントの description を見て、「このタスクにはresearcherが適切」と自動判定して呼び出します。明示的に名指しすることも可能です(例:「researcherエージェントに調べさせて」)。

## 5. 並列実行させたい場合
複数の独立したリサーチを同時に走らせたいときは、そう明示します。
> researcherに「睡眠」「運動」「食事」の3テーマを並行して調べさせてください
Claude Codeは複数のサブエージェントを並列起動できます(それぞれ独立したコンテキストウィンドウで動くため、メインの会話が肥大化しません)。

## 6. ツール権限を絞る
各エージェントの tools: フィールドで使えるツールを制限できます。例えばeditorには編集系ツールのみ、researcherには検索系ツールのみ、というように権限分離しておくと、意図しない操作(ファイル削除など)を防げます。

## 7. /agents コマンドで管理
Claude Code上で /agents と打つと、定義済みのサブエージェント一覧をインタラクティブに確認・作成・編集できるUIが出ます。手書きでMarkdownファイルを作る代わりに、対話形式で作成することも可能です。
